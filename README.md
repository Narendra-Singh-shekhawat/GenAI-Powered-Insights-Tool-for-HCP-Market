## Overview

This project is a GenAI-powered insights tool designed for pharmaceutical commercial and insights teams. It combines unstructured market research content and structured sales data so business users can ask natural language questions and receive meaningful, evidence-backed answers.

The proof of concept demonstrates how to connect:
- Market Research (MR) data such as transcripts, PDFs, and PowerPoint summaries
- Sales Performance data such as HCP-level prescription trends, product performance, and rep engagement

The goal is to answer questions like:

> “What are the most common objections raised by endocrinologists whose prescription volume dropped in the past 2 quarters?”

---

## Business Objective

Commercial and insights teams often have useful information spread across multiple disconnected sources:
- HCP interview transcripts
- Market research summaries
- Slide decks
- Sales tables
- Call activity logs
- Product performance reports

This project aims to bring these sources together into a unified GenAI workflow that can:
- understand business questions in plain English
- retrieve relevant MR evidence

## How the System Works

The system combines document retrieval with structured analytics.

### Step 1: Ingestion
The ingestion pipeline reads:
- transcript text files
- PDF files
- PowerPoint files

It extracts text and prepares content for downstream indexing.

### Step 2: Embedding and Vector Indexing
The extracted MR content is transformed into embeddings and indexed in Weaviate. This enables semantic search over unstructured content.

### Step 3: Structured Sales Querying
Sales-related metrics are queried from a structured database using PostgreSQL.

This includes:
- HCP prescription trends
- product performance changes
- rep engagement or call metrics

### Step 4: Retrieval + Analysis
When the user submits a question:
- the retriever fetches relevant MR snippets from Weaviate
- the sales query service fetches structured business facts from PostgreSQL
- the query engine combines both sources into a unified answer

### Step 5: Final Response Generation
The system produces a final response with:
- summarized insights
- supporting evidence
- debug information for transparency

## Component-Level Explanation

### `ingestion_pipeline.py`
Handles document ingestion for:
- transcripts
- PDF files
- PowerPoint slides

Its job is to read and normalize source content.

### `embedding_pipeline.py`
Converts extracted MR content into vector embeddings and pushes them to Weaviate.

### `retriever.py`
Performs semantic retrieval from Weaviate to fetch relevant MR snippets.

### `sales_query_service.py`
Fetches structured commercial and sales data from PostgreSQL.

### `postgres_client.py`
Manages PostgreSQL database connectivity.

### `weaviate_client.py`
Handles interaction with Weaviate for vector storage and retrieval.

### `query_engine.py`
Acts as the orchestration layer:
- accepts user query
- retrieves MR evidence
- retrieves sales evidence
- combines both into final answer generation

### `reset_weaviate_schema.py`
Used for resetting or recreating Weaviate schema during development.
